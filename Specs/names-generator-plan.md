# План: генератор имён, городов и улиц заданной длины

Статус: реализовано в ветке `feature/name-generator` · Дата: 2026-10-22

> **Уточнения после реализации (2026-10-22):** на малых длинах лишние слова отбрасываются, пока на каждое не придётся примерно 3 буквы. Поэтому Full name длиной до 5 символов без Spaces — это одно имя (`Brian`), а Street короче 6 символов — одна основа без типа (`Elm`). Длинные слова (больше 14 букв) склеиваются в основном из настоящих слов словаря (`Ashfordlincolnbrook`), а не только из марковских кусков.
>
> **Длинные значения без пробелов (2026-10-22):** длинные значения делятся на слова обычной длины, примерно одно слово на 8 символов, для всех полей. Без пробелов слова склеиваются в CamelCase (`TheodoreFlorenceIsabel`) вместо одного слова в нижнем регистре. Если у однословного поля (Name, Surname, City) включено только тире, длина растёт за счёт частей через тире (`Mary-Jane-Anna-Rose`), а не за счёт двух огромных частей.

## 1. Цель и рамки

Генерировать **правдоподобные** значения для полей Name, Surname, Full name, City и Street **точно заданной длины**. Генератор нужен для проверки граничных значений в валидациях: минимальной и максимальной длины, допустимых символов, пробелов, тире и апострофов.

**В рамках задачи:**
- Пять полей: Name, Surname, Full name, City, Street.
- У каждого поля есть ввод длины и четыре чек-бокса: Spaces, Hyphens, Apostrophes и Any characters. Первые три сочетаются в любой комбинации. Any characters блокирует их, потому что разрешает всё.
- Общая кнопка **Generate** заполняет все поля сразу. После генерации у каждого поля появляется иконка копирования.
- Значение похоже на настоящее, а не на случайный набор букв. Исключение — режим Any characters (§4.6).
- Мужские и женские имена не различаются. Размер словарей не принципиален.

**Вне рамок:** локализация имён под конкретные страны, номера домов и полные почтовые адреса, генерация массивов значений (архитектура позволяет добавить её позже, §10).

## 2. Принятые решения (по итогам уточнения требований)

| Вопрос | Решение |
|---|---|
| Faker или своё решение | **Своё решение: встроенные словари и марковская цепь по буквам.** Faker не подгоняет значения под точную длину и не умеет делать длинные значения, а CLAUDE.md запрещает внешние зависимости. Бандл Faker весит сотни КБ, а нужны только 5 категорий. |
| Full name и Street без пробелов (режим по умолчанию) | **Склейка в CamelCase:** `JohnSmith`, `OakStreet`. |
| Смысл чек-боксов Spaces, Hyphens и Apostrophes | **Символ обязательно присутствует** в значении, а не просто разрешён. Так граничный кейс гарантированно проверяется. |
| Апостроф | Отдельный чек-бокс **Apostrophes**, добавлен по запросу после первой версии плана. Символ — ASCII `'` (U+0027). Он ведёт себя так же, как Spaces и Hyphens: сочетается с ними в любой комбинации и блокируется режимом Any characters. Типографский `’` (U+2019) не используется (§10). |
| Содержимое режима Any characters | **Unicode-буквы:** латиница с диакритикой (`José`, `Müller`), кириллица, греческий, CJK. Пробелы, тире и апострофы тоже разрешены. Цифры, ASCII-спецсимволы, эмодзи и injection-строки **не входят** (§10). |

## 4. Алгоритм генерации

### 4.1 Словари (`js/names.js`)
Только ASCII-латиница: значения с диакритикой и апострофами в словари не попадают.
- `FIRST_NAMES` — около 200 мужских и женских имён вперемешку (`Al`, `Bo`, `Ed`, `Anna`, `Christopher`…). Короткие имена из 2 букв нужны для малых длин.
- `LAST_NAMES` — около 200 фамилий.
- `CITIES` — около 200 городов из одного слова (`Boston`, `Springfield`, `Manchester`…). Многословные города собираются из частей (§4.4).
- `CITY_PREFIXES` (`New`, `Saint`, `Port`, `Fort`, `Lake`, `North`…) и `CITY_SUFFIXES` (`City`, `Falls`, `Springs`, `Heights`…).
- `STREET_NAMES` — около 150 основ (`Oak`, `Maple`, `Washington`, `Highland`…).
- `STREET_TYPES` — разной длины: `Way` (3), `Lane`, `Road` (4), `Drive`, `Court`, `Place` (5), `Street`, `Avenue` (6), `Terrace` (7), `Crescent` (8), `Boulevard` (9).
- `APOSTROPHE_PREFIXES` — `O'`, `D'`, `L'` для форм `O'Brien`, `D'Angelo`, `L'Anse` (§4.4). Притяжательная форма `'s` (`King's`) собирается в коде, отдельный словарь не нужен.

Каждый словарь при загрузке индексируется по длине: `byLength[n] → [words]`. Так слово нужной длины выбирается за O(1).

### 4.2 Марковская модель
Для каждой категории (имена, фамилии, города, улицы) при загрузке страницы строится цепь **порядка 2** по буквам в нижнем регистре, с маркерами начала `^^` и конца `$`.

`markovWord(model, n)` генерирует слово **ровно из n букв**:
1. Контекст — две последние буквы (в начале `^^`). Следующую букву выбираем по весам переходов, **исключая** `$`.
2. На последней позиции вес буквы `c` умножаем на вероятность окончания после неё: `P(c | ctx) · P($ | ctx₂ + c)`. Так слово заканчивается «естественно» (`-son`, `-ton`, `-a`, `-ley`).
3. Если для контекста нет данных, переходим к порядку 1, а если нет и их, чередуем гласные и согласные.
4. Фильтр: не больше 2 одинаковых букв подряд и не больше 3 согласных подряд. Если слово не проходит, генерируем заново (до 20 попыток), затем принимаем последний вариант.
5. Первая буква заглавная.

Пример результата: `Marlington`, `Brenley`, `Kathorine`.

### 4.3 Слово заданной длины: `fitWord(category, n)`
1. Если в словаре есть слова длины `n`, с вероятностью 70% берём одно из них. Иначе (и в остальных 30% случаев) возвращаем `markovWord(model, n)`. Это даёт разнообразие при повторных нажатиях.
2. При `n = 1` возвращаем случайную заглавную букву.
3. При `n > 14` одно марковское слово становится неправдоподобным. Поэтому собираем **составное слово** из 2–4 марковских частей по 4–9 букв, слитно и без внутренних заглавных: `Marlingtonbrook`. Длины частей подбираются так, чтобы сумма была ровно `n`.

### 4.4 Структура значения: слова и составные части
Любое значение описывается как список **слов**, где каждое слово может быть **составным через тире** (`Mary-Jane`), а каждая часть может содержать **апостроф** (`O'Brien`). Рендеринг одинаков для всех полей:
- Слова соединяются пробелом, если включён Spaces, и склейкой CamelCase, если нет.
- Составные части внутри слова соединяются тире, если включён Hyphens. Без Hyphens составных слов нет.
- Апостроф появляется в части слова только при включённом Apostrophes (§4.4.1).

| Поле | Без флагов | Spaces | Hyphens | Spaces + Hyphens |
|---|---|---|---|---|
| Name | `Anna` | `Anna Maria` | `Mary-Jane` | `Mary-Jane Ann` |
| Surname | `Smith` | `Van Dyke` | `Smith-Jones` | `De La Cruz-Smith` |
| Full name | `JohnSmith` | `John Smith` | `JohnSmith-Jones` | `Mary-Jane Smith` |
| City | `Springfield` | `New Haven` | `Winston-Salem` | `Saint-Denis Falls` |
| Street | `OakStreet` | `Oak Street` | `Oak-HillRoad` | `Oak-Hill Road` |

`buildValue(field, n, opts)`:
1. **Шаблон слов** задаётся для каждого поля. Например, Full name — это `[First] [Last]`, а при большой длине и включённом Spaces `[First] [Middle] [Last]`. Street — это `[StreetName…] [StreetType]`, а City — `[Prefix]? [CityName] [Suffix]?`.
2. **Обязательность символов.** Spaces требует хотя бы 2 слов, Hyphens — хотя бы одного составного слова, а Apostrophes — хотя бы одной части с апострофом.
3. **Распределение длины.** `n` минус число разделителей распределяется между частями. Сначала фиксируются части из словаря с известной длиной (например, `StreetType`). Остаток делится между свободными частями случайно, но не меньше 2 букв на часть, если общая длина это позволяет.
4. Каждая часть заполняется через `fitWord` своей категории.
5. **Длинные значения** (больше 25 символов): при включённом Spaces добавляем слова (средние имена, несколько основ улицы — `Martin Luther King Avenue`), без Spaces длина набирается CamelCase-склейкой слов. Части длиннее 14 символов строятся как составные (§4.3).

#### 4.4.1 Апостроф
Апостроф ставится в одной из двух реальных позиций, а не в случайном месте:
- **Префикс** `O'`, `D'` или `L'` перед частью с заглавной буквы: `O'Brien`, `D'Angelo`. Префикс занимает 2 символа длины, остаток части заполняется через `fitWord`.
- **Притяжательная форма** `'s` в конце части: `King's`, `John's`. Занимает 2 символа.

| Поле | Форма | Apostrophes | Apostrophes + Spaces | Apostrophes + Hyphens |
|---|---|---|---|---|
| Name | префикс `D'` | `D'Andre` | `D'Andre Lee` | `D'Andre-Lynn` |
| Surname | префикс `O'` / `D'` | `O'Brien` | `Van O'Neil` | `O'Brien-Smith` |
| Full name | префикс в фамилии | `JohnO'Brien` | `John O'Brien` | `MaryJane-O'Brien` |
| City | `'s` или префикс `L'` | `L'Anse` | `Saint John's` | `Bishop's-Stortford` |
| Street | `'s` в основе | `King'sRoad` | `King's Road` | `King's-HillRoad` |

Если включено несколько флагов, апостроф и тире могут оказаться в одной части (`O'Brien-Smith`), но никогда не стоят рядом друг с другом или с пробелом.

### 4.5 Минимальная длина и ошибки ввода
Минимально возможная длина зависит от флагов:

| Флаги | Минимум | Пример |
|---|---|---|
| нет | 1 | `A` |
| Spaces | 3 | `A B` |
| Hyphens | 3 | `A-B` |
| Spaces + Hyphens | 5 | `A-B C` |
| Apostrophes | 3 | `O'B` |
| Apostrophes + Spaces | 5 | `O'B C` |
| Apostrophes + Hyphens | 5 | `O'B-C` |
| Spaces + Hyphens + Apostrophes | 7 | `O'B-C D` |
| Any characters | 1 | `É` |

Общая формула: 1 + 2 за каждый включённый флаг. Если длина меньше минимума, поле не генерируется. Под строкой появляется `.field-error`, например: *«Min length with spaces and hyphens is 5»*.

Ввод длины — `<input type="number" min="1" max="1000" placeholder="auto">`.
- **Пусто** — случайная длина в разумном для поля диапазоне (`DEFAULT_RANGES`): Name 3–10, Surname 4–12, Full name 8–25, City 4–15, Street 8–25. Нижняя граница поднимается до минимума из таблицы выше.
- **Не целое число, 0, отрицательное или больше `MAX_LENGTH` (1000)** — ошибка в строке поля. Остальные поля генерируются как обычно.

`MAX_LENGTH = 1000` — константа. 1000 покрывает типичные лимиты 50, 100 и 255 вместе с проверкой `+1`.

### 4.6 Режим Any characters (Unicode)
- При включении Any characters чек-боксы Spaces, Hyphens и Apostrophes отмечаются и блокируются (`disabled`), показывая, что эти символы уже разрешены. При выключении восстанавливается их прежнее состояние.
- Значение строится так же, как в §4.4, но пробелы, тире и апострофы **разрешены, а не обязательны**: каждый включается случайно с вероятностью 50%. Затем 30–60% букв заменяются символами из Unicode-наборов:
  - латиница с диакритикой (только **предсоставленные** символы NFC): `á é í ó ú ñ ç ü ö ä ß ø å ł ž š č…`;
  - кириллица: `А–я`, `ё`;
  - греческий: `α–ω`;
  - CJK: небольшой набор иероглифов из базовой плоскости (`中 山 田 李 王…`).
- **Гарантия:** в значении есть хотя бы один не-ASCII символ.
- Все символы из базовой плоскости (BMP) и без комбинируемых диакритических знаков. Поэтому `value.length` в JS совпадает с числом видимых символов, и длина однозначна для любого валидатора: UTF-16, кодовые точки или графемы. Для длины в **байтах** (UTF-8) это не так: кириллица занимает 2 байта, CJK — 3. В подсказке на странице это нужно сказать.

### 4.7 Самопроверка перед выводом (по образцу `validateIBAN`)
`validateValue(value, n, opts)`:
- `value.length === n`.
- Без флагов: `^[A-Za-z]+$`.
- Любая комбинация Spaces, Hyphens и Apostrophes: только `[A-Za-z]` и символы включённых флагов (пробел, `-`, `'`). Каждый включённый символ присутствует. Символов выключенных флагов нет.
- Any characters: `^[\p{L} '-]+$/u` и хотя бы один символ `[^\x00-\x7F]`.
- Для всех режимов: нет пробела, тире или апострофа в начале строки, нет пробела и тире в конце, нет двух разделителей подряд (пробел, тире и апостроф считаются разделителями).

Если проверка не прошла, генерируем заново, не более 5 попыток, затем показываем ошибку в строке поля.

```html
<div class="field-row">

  <div class="field-options">

  </div>

    <span class="len-badge" id="firstNameLen"></span>

  </div>

```

- `.btn-row` с одной кнопкой **Generate** (`generateAll()`).
- `<div class="result" id="namesHint">` с подсказкой: *«Leave length empty for a random realistic length. Any characters adds Unicode letters (accents, Cyrillic, Greek, CJK); length is counted in characters, not bytes.»*
- При загрузке **не** генерируем: по требованию иконка копирования появляется после нажатия Generate.
- Enter в любом поле длины запускает `generateAll()`.

### Функции в `js/names.js`
- `generateAll()` — для каждого из `FIELDS` читает длину и флаги, вызывает `buildValue` и `validateValue`, пишет результат в `<key>Output`, длину в `<key>Len` (`12 chars`), показывает `<key>CopyBtn`. При ошибке очищает вывод, скрывает иконку и заполняет `<key>Error`.
- `toggleAny(key)` — блокирует или разблокирует Spaces, Hyphens и Apostrophes (§4.6).
- `copyField(key)` — `navigator.clipboard.writeText(output.value)`. Иконка на 1500 мс меняется на галочку (аналог `Copied!`). Значение копируется **без изменений**: пробелы не вырезаем.
- `FIELDS` — таблица полей: `{ key, label, range, template }`, по образцу `cryptoFormats` и `bbanFormats`.

## 8. Проверка

### 8.1 Консольный самотест
Функция `selfTestNames()` в `names.js` (не вызывается из UI). Для каждого поля, каждой из 9 комбинаций флагов (8 сочетаний Spaces, Hyphens и Apostrophes, включая «нет флагов», плюс Any) и длин `[min, min+1, 2, 3, 5, 10, 25, 50, 100, 255, 256, 1000]` генерирует по 200 значений и проверяет `validateValue`. Результат выводится через `console.table` — число сбоев на комбинацию, ожидается 0. Длины ниже минимума должны давать ошибку, а не значение.

### 8.2 Ручные сценарии UI
- **Длины:** пусто (случайная в диапазоне поля), 1, 2, 3, 5, 50, 255, 256, 1000. Ошибки: 0, −1, 2.5, 1001. Бейдж длины совпадает с введённым значением.
- **Флаги:** каждая комбинация на каждом поле. Пробел, тире и апостроф присутствуют, когда включены, и отсутствуют, когда выключены. Апостроф стоит в реальной позиции (`O'…`, `D'…`, `L'…`, `…'s`). Any блокирует Spaces, Hyphens и Apostrophes, а при снятии восстанавливает их состояние.
- **Слишком малая длина для флагов** (Spaces + Hyphens, длина 4; все три флага, длина 6) — понятная ошибка только в этой строке, остальные поля заполнены.
- **Апостроф при копировании:** во внешней форме вставляется ASCII `'`, а не типографский `’`.
- **Правдоподобие:** 10 нажатий на длинах 6, 12, 30 и 100. Значения читаемы и разнообразны, нет `Xqzzt`-подобных сочетаний.
- **Копирование:** иконка скрыта до первой генерации. Копируется точное значение, включая Unicode. Галочка исчезает через 1500 мс. При ошибке иконка скрыта.
- **Вставка во внешнюю форму:** значение с Unicode после вставки имеет ту же длину (проверка, что нет комбинируемых символов).
- **Вёрстка:** длина 1000 не ломает карточку (поле прокручивается внутри), на ширине телефона строка настроек переносится.
- Chrome, Firefox, Safari. Карточка на главной ведёт на страницу, breadcrumb — обратно.

## 9. Критерии готовности
- [ ] `selfTestNames()` — 0 сбоев на всех комбинациях.
- [ ] Значения точно заданной длины для 1–1000 при всех допустимых комбинациях флагов.
- [ ] Без флагов — только `[A-Za-z]`. Включённый Spaces, Hyphens или Apostrophes гарантирует наличие символа.
- [ ] Any characters содержит хотя бы один не-ASCII символ, длина однозначна (BMP, NFC).
- [ ] Нет внешних зависимостей и ES-модулей. Новые CSS-классы общие и описаны в CLAUDE.md.
- [ ] `CLAUDE.md` обновлён: таблица генераторов, описание алгоритма, отступление из §3.

## 10. Риски и открытые вопросы
- **Any characters не содержит цифр и ASCII-спецсимволов.** По формулировке требования («любые символы кроме букв») их можно было ожидать, но по итогам уточнения выбраны только Unicode-буквы. Если нужны цифры, `!@#$…` или эмодзи, их легко добавить отдельным набором в §4.6. Для эмодзи придётся решить, что считать длиной.
- **Типографский апостроф `’` (U+2019).** Его подставляют iOS и macOS при «умной пунктуации», и он часто проходит валидацию иначе, чем `'`. Сейчас генерируется только ASCII `'`. Если нужно, можно включать `’` в режиме Any characters или добавить переключатель вида апострофа.
- **Правдоподобие на больших длинах.** Значение в 255 символов без пробелов всегда будет выглядеть искусственно. Это приемлемо для теста максимальной длины.
- **Массивы значений.** Если понадобится сгенерировать N значений сразу (например, для data-driven тестов), `buildValue` уже чистая функция. Достаточно добавить поле Count и вывод в `<textarea>`.
